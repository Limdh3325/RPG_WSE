# 22. 에이전트 작업 측정

**한국어** | [English](en/22-agent-work-measurement.md)

2026-11-15부터 수행하는 작업을 대상으로 한다. 과거 작업은 확보된 증거만 연결하고 소급 점수를 추정하지 않는다. 평가 단위는 채팅 횟수가 아니라 검증 가능한 결과를 갖는 작업 `WORK-YYYYMMDD-NN`이다. 날짜는 Asia/Seoul 기준이며 같은 날짜의 번호는 중복되지 않게 정한다.

## 기록 위치와 시점

- 착수: [요청 템플릿](../inbox/TEMPLATE.md)을 복사하고 [현재 작업 색인](work-index.md)에 등록한다. 사용자 요청, 전달 맥락, 기준 커밋·작업 트리, 범위, 관련 REQ/TASK/ADR/TEST와 인수 조건을 적는다. 관련 ID가 없으면 이유와 함께 해당 없음으로 표시한다.
- 진행: 요구사항 변경과 설계 의도, 실패한 접근과 수정, 사람의 판단, 실제 위임 내용을 시간순으로 추가한다. 원래 인수 조건은 보존하며 추가·제외 이유와 결정 주체를 기록한다.
- 완료: [결과 템플릿](../outbox/TEMPLATE.md)에 각 인수 조건의 검증 명령·환경·결과·증거를 연결한다. 변경 파일, 커밋/PR, 통합 대상과 결과를 구분한다. 로컬 변경만 있으면 미커밋·미통합으로 명시한다.
- 후속: 나중에 발견한 오류는 원래 작업의 결과 기록에 발견일, 영향, 누락 원인, 수정 작업, 재검증을 추가한다. 발견되지 않은 오류를 0건의 보증으로 표현하지 않는다.

요청과 결과는 같은 WORK ID를 파일명에 쓴다. 색인은 위치와 상태만 요약하고 상세 내용은 중복하지 않는다. 상태는 IN PROGRESS / BLOCKED / DONE이며 DONE은 해당 작업의 인수 조건 충족을 뜻한다. 통합·배포가 범위에 포함되면 해당 증거도 필요하다. 제외·유예는 변경 기록에 명시한다. 후속 결함의 미해결 여부는 색인에 별도로 표시한다.

## 네 평가 기준과 지표

| 기준 | 필수 증거 | 측정 |
|---|---|---|
| 작업·맥락·검증 기준 전달 | 최초 요청, 참조 자료, 범위, 인수 조건, 위임 시 실제 전달 내용 | 착수 전 인수 조건을 기록한 작업 수 / 기간 내 착수 작업 수; 맥락 누락으로 재작업한 건수 |
| 요구사항·설계 의도 유지 | REQ/ADR→인수 조건→변경 파일→검증 연결, 변경 이유·주체 | 증거가 PASS인 인수 조건 수 / 현재 적용 인수 조건 수; 근거 없이 변경된 조건 수 |
| 검증·통합·놓친 오류 | 실행 결과, 대상 버전·환경, 통합 증거, 후속 결함 | 통합 실패 건수; 완료 후 발견된 결함 수와 영향 |
| 사람의 판단·실패 수정 | 판단 요청 이유·선택지·결정자·결과, 실패 원인·수정·재검증 | 수정한 실패 접근 중 재검증한 건수 / 수정한 실패 접근 수; 같은 원인의 재발 건수 |

집계에는 기간, 대상 WORK ID, 분자·분모, 관찰 종료일을 함께 적는다. 분모가 0이면 N/A로 표시한다. 인수 조건을 제외해 비율을 올리지 않도록 최초 조건 수와 추가·제외 내역도 공개한다. 결함은 동일 원인의 중복 보고를 구분하고 데이터 유실·기능 차단 등 실제 영향을 적는다. 질문 횟수가 적거나 테스트 개수가 많다는 사실만으로 좋은 평가를 주지 않는다.

검증 결과는 PASS / FAIL / SKIP / NOT RUN으로 구분한다. DB 연결 없이 skip된 성공 프로세스는 DB 검증 PASS가 아니다. 로그 전체 대신 재현 가능한 명령과 비밀값을 제거한 결과 요약·보존 위치를 남긴다. 외부 CI 증거는 실행 URL과 대상 커밋을 함께 기록한다. 로컬 로그가 Git에서 제외된다면 사라질 수 있는 경로만을 유일한 증거로 삼지 않는다.

선택적으로 각 기준의 추적 가능성을 0점(기록 없음), 1점(설명만 있음), 2점(증거 있음), 3점(요청부터 결과·후속까지 연결됨)으로 평가한다. 이는 소프트웨어 품질 점수가 아니다. 증거 부족과 해당 없음을 구분한다.

## 문서 유지

기존 요구사항·ADR·테스트 문서가 기준이며 작업 기록은 해당 문서를 연결한다. 과거 [개발 상태표](20-development-status.md)는 보존한다. 현재 진행 작업은 별도 색인에서 추적한다.

번호가 있는 설계 문서는 한·영 대응본과 생성물을 함께 갱신한다. 작업 색인과 요청·결과 기록은 한국어 공통 운영 기록이며 건별 번역을 요구하지 않는다. 이 문서의 영어판에서도 같은 기록을 연결한다. 비밀값, 개인정보, 내부 사고 과정 대신 외부에서 검토 가능한 결정 이유와 실행 증거를 기록한다.
